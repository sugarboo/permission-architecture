# Permission Center Nuxt Demo

企业中台权限中心的 Nuxt 4 纯静态交互 Demo。

> 本项目用于方案评审和界面演示。数据保存在浏览器本地模拟仓库中，不连接生产数据库，也不承担真实鉴权。生产系统必须在可信后端完成身份认证、资源校验、审计和缓存失效。

## 已演示能力

- 用户列表、创建、状态筛选和授权抽屉；
- 角色列表、创建和授权抽屉；
- 用户角色多选，角色区域优先展示；勾选角色后实时反显其菜单和资源来源；
- 板块 → 目录 → 页面菜单树；
- 业务资源目录；
- 菜单 CORE / OPTIONAL 资源包；
- 角色或直授带来的菜单会使 CORE 在资源页签自动反显；
- OPTIONAL 使用黄色高亮，并区分角色已授、用户已授和待选；
- 组织树、岗位列表和用户主任职；
- 设置任职时可选补录工号；
- 有效权限来源解释和 Mock 审计；
- 浏览器刷新后保留模拟数据，并可重置。

## 当前界面口径

- 角色没有板块字段；
- 用户列表不显示内部策略版本；
- 创建用户只填写姓名、登录账号和状态；
- 创建用户不填写工号、组织、岗位或角色；
- 工号仅在组织与岗位页面设置任职时选填；
- 用户授权抽屉先多选角色，再配置菜单和资源；角色投影只读，不会被保存为用户直授；
- 用户授权失效时间选填；
- 菜单 CORE 自动生效，OPTIONAL 不自动授予。

当前 Demo 不包含数据域、数据范围、客户数据行或权限模拟器交互。它们不是本项目当前实现范围。正式后端可在后续阶段单独建设岗位数据边界。

## 领域规则

### 业务资源码

资源码是唯一功能授权原子：

```text
crm.customer.read
crm.customer.export
sc.purchase_order.create
sc.purchase_order.approve
```

API URL、HTTP Method、Vue 组件和数据库表名不作为权限标识。

### 编码前缀

```text
BOARD_INFO
DIR_INFO_CUSTOMER
MENU_INFO_CUSTOMER_LIST
ROLE_SALES_MANAGER
```

- 板块：`BOARD_`；
- 目录：`DIR_`；
- 页面菜单：`MENU_`；
- 角色：`ROLE_`；
- 资源：`<domain>.<object>.<action>`。

### 有效资源

```text
角色显式资源
∪ 角色菜单 CORE
∪ 用户直接资源
∪ 用户直接菜单 CORE
```

同一资源按 ID 去重，并保留 `ROLE`、`DIRECT`、`MENU_CORE` 等来源用于解释。

## 本地运行

Node.js 要求见 `package.json`。

```bash
pnpm install
pnpm dev
```

默认地址：<http://127.0.0.1:3000/>

## 验证

```bash
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
```

`pnpm build` 使用 Nuxt static preset 生成静态站点。

## 数据与重置

模拟数据写入浏览器 localStorage。若旧版数据结构与当前版本不兼容，应用会使用新的 schema key 初始化。演示后可通过界面重置，或清除本网站存储恢复初始数据。

## 生产化要求

将 Demo 接入真实系统时至少需要：

1. 用 Session 或 OIDC 建立可信 Principal；
2. 将模拟仓库替换为真实 API 和关系数据库；
3. 在所有业务服务方法校验资源码；
4. 由后端返回有效菜单树和资源码集合；
5. 用版本控制并发发布和缓存失效；
6. 将授权关系、版本、审计和 outbox 放在同一事务；
7. 对停用、过期、多来源、HIGH CORE、并发和绕过路径编写测试；
8. 确保生产构建不包含 Mock 数据仓库。

若后续建设岗位数据边界，应作为后端独立阶段实现：范围从可信任职解析并下推 SQL，不能由前端提交或过滤。
